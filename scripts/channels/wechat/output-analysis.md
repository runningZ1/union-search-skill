# 微信公众号输出结果分析

## 容量表与结果留样

| 入口 | 官方单次上限 | 模块默认 | 分页 | `limit` 或数量参数作用 |
| --- | --- | --- | --- | --- |
| Node 文章搜索 | 搜狗微信固定每页条数与最大条数未公布 | `num=10`，本地累计最多 50 | 按 `ceil(min(N,50)/10)` 请求最多五页，遇到空页停止 | `num` 控制请求页数估算与最终切片，不保证足额；统一 limit 不适用 |
| Python 公众号搜索 | 搜狗微信固定每页条数与最大条数未公布 | `max_results=10`，无固定本地数字上限 | 仅请求一页 | max_results 仅本地切片，`0` 返回空数组；统一 limit 不适用 |

真实文章结果见 [搜索结果样例](examples/search-result.json)。文件保存独立 Node 入口返回的 `{query,total,articles}` 对象，属于独立响应证据层；未使用统一 CLI 渠道容器，未保存原始 HTTP HTML。3 条文章样例用于核对公开 Node 输出，Python 公众号字段未留样；容量依据下文已有资料与实现。

## 常用参数与返回数量

资料整理日期：2026-10-25。依据 `search_wechat.js`、`wechat_no_api.py` 与 `no_api/base_engine.py`；此次未重新执行网页搜索。

| 参数 | 含义 | 默认值或未指定行为 | 范围与实际约束 |
| --- | --- | --- | --- |
| Node `query` | 文章关键词 | 必填 | 搜狗微信 HTML，固定 `type=2` |
| Node `-n/--num` | 累计文章数量目标 | `10` | 正整数按 `min(N,50)` 处理；CLI 的 0 或无法解析值变为 10，负数会使循环不执行；没有不限模式 |
| Node `-r/--resolve-url` | 解析搜狗跳转链接 | `false` | 逐条额外请求；仅改变 URL 处理，不增加搜索条数 |
| Node `-o/--output` | JSON 文件位置 | 不写文件，输出 stdout | 指定文件后仍输出同一 JSON |
| Python `query` | 公众号关键词 | 必填 | 固定搜狗微信 `type=1`，资源类型为公众号 |
| Python `-m/--max-results` | 单页解析结果的本地截断 | `10`，函数 search_wechat 同为 10 | 无固定数字上限、无正数校验；0 切片为空，负数采用 Python 负索引切片语义 |
| Python `--proxy` / `--json` | 代理与输出格式 | 无显式代理、文本 | proxy 为地址；json 开关不改变数量 |
| 基类方法 `timeout` | Python 单请求超时 | `15` 秒 | Python CLI 没有暴露对应参数 |

**搜狗微信 HTML 没有在已读取的官方入口中承诺固定每页条数或 API 搜索数量上限。** Node 模块本地累计最多输出 50 篇文章，页数按 `ceil(min(N,50)/10)` 计算，最多请求五个搜索页面；10 是代码估算每页容量所用值，不能作为官方每页固定 10 条的承诺。页面实际可解析结果不足时不保证补足 N，遇到空页即停止，最后再按目标数量切片。

Python 公众号模块只请求一个页面，max_results 仅在 HTML 解析后切片，不向页面发送数量参数，也不翻页。它没有固定的本地数字上限，输出上限由该次页面实际解析出的数量决定，默认最多保留 10。Node 与 Python 均未接入当前统一 CLI 注册表，统一 `--limit` 不作用于这两个独立入口，也不能通过取消统一限制扩大数量。

Cookie、验证码、访问频率、搜狗索引覆盖、页面结构与跳转链接有效期都会动态影响结果。微信内容开放接口的其他参数不适用于这里使用的搜狗 HTML 页面，不能借用其数字作为上限。

官方来源（资料整理日期：2026-10-25）：[搜狗微信搜索入口](https://weixin.sogou.com/)。已核对页面入口，未发现固定每页数量承诺；50 条与最多五页均为本实现限制。

## 覆盖入口与来源

本目录公开入口为 `node search_wechat.js <关键词> -n <数量>`，通过搜狗微信搜索 HTML 提取文章；未注册为统一 CLI 渠道。JSON 顶层为 `query`（string）、`total`（integer，实际数组长度）、`articles`（array）。输出文件与 stdout 使用同一 JSON；诊断写入 stderr。

## 文章字段

| 字段 | 类型 | 来源及缺失规则 |
|---|---|---|
| `title` | string | 搜索卡片 `h3 a` 文本；无标题链接的卡片跳过 |
| `url` | string | 标题链接 href；相对路径补搜狗微信域名，缺失可为空字符串 |
| `summary` | string | 卡片 `p.txt-info` 文本，缺失为空字符串；不含正文 |
| `datetime` | string | 从卡片脚本时间戳或相对时间推导；无法解析为空字符串，显示为日期时间文本 |
| `date_text` | string | 中文年月日显示值，缺失为空字符串 |
| `date_description` | string | 根据当前时间算出的“刚刚/若干小时前/若干天前”或页面原始时间文字，缺失时取 date_text |
| `source` | string | `.all-time-y2` 或 `a.account` 文本，通常为公众号名称；缺失为空字符串 |

卡片没有阅读数、点赞数、作者 ID、公众号唯一 ID、相关性分数、品牌或商品价格等字段。数组顺序来自搜索页面，不单独输出 rank。

## 地址与日期边界

默认 url 是 `weixin.sogou.com/link?...` 跳转地址，可能带有临时查询参数，不能保证长期有效。启用 `--resolve-url` 时逐条尝试解析真实地址，输出仍使用 url 字段；本轮未启用，不能假定 url 都是 `mp.weixin.qq.com` 原文链接。

三个日期字段由不同代码路径格式化：datetime 使用中国时区格式化函数，而 date_text 的时间戳路径使用 Node 本地日期方法，date_description 又依赖运行时当前时间。实测出现同一条 datetime 与 date_text 日期不同的情况，因此这三者不具备严格的一致性保证；不得将多个显示字段直接当作可互换的标准时间。文档只描述当前输出，未修改日期实现。
