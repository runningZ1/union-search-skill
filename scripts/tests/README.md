# 代码回归测试目录

`scripts/tests/` 统一存放验证本项目 Python 代码行为的自动化回归测试源码，以及这些测试的执行说明。测试对象包括渠道适配代码、搜索编排、结果处理、能力注册表和 CLI 参数与输出逻辑。本目录中的文件随项目代码提交。

## 文件范围

允许存放：

- 按 `test_<功能名称>.py` 命名、使用 Python `unittest` 的测试模块。
- 被多个测试模块直接导入的测试辅助代码；辅助代码不得提供生产功能，也不得生成伪造响应或替代真实依赖。
- `README.md` 中的目录职责、执行命令和验证限制说明。

下列文件按用途存放在指定位置：

| 文件类型 | 存放位置 |
| --- | --- |
| 技能触发案例、触发评估配置和技能结构验证说明 | `scripts/evals/` |
| 生产代码、渠道实现和运行配置 | `scripts/` 下对应功能模块 |
| 渠道真实搜索样例及来源说明 | `scripts/channels/<渠道>/examples/` |
| 临时验证脚本、测试报告、运行日志、下载文件和其他任务中间结果 | 根目录 `.work/` |
| 搜索入口自动生成的结果归档 | 根目录 `output/`，由搜索入口管理 |
| 凭据和本地环境配置 | 根目录 `.env` 或用户指定的本地凭据位置；不得写入测试文件或提交到版本库 |

不得在本目录保存手工测试记录、运行结果、业务数据、依赖安装目录、复制的第三方实现、mock、伪造响应或用于绕过失败的特殊处理。

## 测试编写与执行

- 项目规则以根目录 [AGENTS.md](../../AGENTS.md) 为准。
- 测试必须验证可观察的实际行为，使用真实代码、真实注册表和真实依赖。涉及外部服务时，必须检查实际响应、来源或生成文件。
- 测试模块必须能够被 `unittest discover` 发现。模块顶层只定义测试、辅助函数和必要的导入，不在导入时发起网络请求。
- 当前测试文件位于本目录这一层，通过 `Path(__file__).resolve().parents[2]` 定位项目根目录。外部调用的工作目录不得影响代码导入路径。
- 每项测试的失败必须直接报告；不得捕获失败后改用其他实现、伪造结果或将失败转为成功。
- 执行前检查所选测试是否使用 mock、伪造数据或不允许的临时路径。包含这些行为的用例不得执行，也不得作为当前任务的验证证据。
- 测试通过只能证明该测试实际覆盖的行为。本地注册表检查通过不能证明远程搜索服务可用。

## 当前可执行的注册表检查

在项目根目录执行：

```bash
python -m unittest discover -s scripts/tests -p test_platform_groups.py -v
```

该命令读取项目真实注册表，检查渠道数量、凭据分区、分组成员与顺序、分组元数据以及兼容渠道的实现映射，不请求外部服务。

从其他工作目录执行时，将 `-s` 指定为本目录的绝对路径：

```bash
python -m unittest discover -s "<项目绝对路径>/scripts/tests" -p test_platform_groups.py -v
```

| 文件 | 验证对象 | 执行限制 |

| `test_ai_tools.py` | 本机工具适配、后端选择与子进程控制 | 包含 mock 和人工构造的响应，按当前规则不执行 |

| `test_unlimited_results.py` | 结果数量参数与输出行为 | 包含 mock 和人工构造的数据，按当前规则不执行 |

当前不得直接执行发现本目录全部测试的命令。目录中的历史用例需要逐项满足项目验证约束后才能纳入执行范围。
